# 🎮 3D CS 風格第一人稱射擊遊戲 (結合 TensorFlow.js 動作控制)

這是一個使用 HTML5 / JavaScript 獨立打造的 3D 第一人稱射擊（FPS）遊戲。它結合了 Three.js 3D 繪圖引擎、Web Audio API 聲效系統，以及 TensorFlow.js (MoveNet 模型)，讓玩家除了能用傳統的鍵盤滑鼠操作外，還能透過網頁攝影機與人體骨架偵測來進行體感瞄準與射擊！

---

## ✨ 主要特色
- **零外部資產依賴**：單一 HTML 檔案即可運行，所有 3D 模型、材質與音效均透過程式碼動態生成或使用 CDN 載入。
- **雙模控制系統**：
  - **傳統模式**：鍵盤 (WASD) 移動、滑鼠指標鎖定瞄準與點擊開火。
  - **AI 體感模式**：透過網路攝影機捕捉 17 處人體骨架關節點，透過身體傾斜與手勢舉高來控制轉向、走位、射擊與換彈。
- **經典反恐精英 (CS) 元素**：包含準心、後座力視效、擊中反饋 (Hitmarker)、爆頭特效與計分機制。
- **程序化音效**：使用 Web Audio API 即時合成槍聲、擊中聲與過關音效，無需額外下載音訊檔案。
- **即時 AI 姿態監視器**：右上角畫中畫面板即時繪製發光骨架連線、分色關節標記點與動作回饋光環。

## 🚀 快速開始指南 (如何使用)

### 1. 執行遊戲
由於本專案使用了 TensorFlow.js 載入模型以及 WebGL/Webcam，建議透過本地伺服器 (Local Server) 來運行，以避免瀏覽器因安全性政策（CORS）阻擋攝影機存取。

- **方法 A（推薦：VS Code）**：
  1. 使用 Visual Studio Code 開啟本專案資料夾。
  2. 安裝 **Live Server** 擴充功能。
  3. 右鍵點擊 `3d_cs_pose_controlled_fps.html`，選擇 **Open with Live Server**（或點擊右下角 Go Live）。

- **方法 B（Python 本地伺服器）**：
  如果您安裝了 Python，可以在專案終端機執行：
  ```bash
  python -m http.server 8000
  ```
  然後打開瀏覽器前往 `http://localhost:8000/3d_cs_pose_controlled_fps.html`。

## 🎯 操作說明

### 模式一：鍵盤與滑鼠（預設）
- **移動**：`W`、`A`、`S`、`D`
- **跳躍**：空白鍵 (`Space`)
- **視角**：移動滑鼠（點擊畫面進入指標鎖定模式）
- **射擊**：滑鼠左鍵
- **換彈匣**：`R` 鍵

### 模式二：AI 攝影機動作控制
在遊戲主選單中，點擊 **Webcam AI Motion** 按鈕並允許瀏覽器存取攝影機。請確保您的上半身（頭部、肩膀、手腕）清晰出現在鏡頭前。

- **瞄準轉向**：頭部與身體向左或向右傾斜（鏡頭將平滑向對應方向轉動）。
- **前後移動**：身體向前靠近鏡頭為前進，向後遠離鏡頭為後退（系統具備自適應基準距離校正）。
- **開火射擊**：將**右手腕**舉高超過肩膀高度即可觸發連續射擊（畫布上右手腕標記點將動態亮起**紅色瞄準光環**）。
- **換彈匣**：將**雙手手腕同時舉高**超過肩膀即可觸發換彈（雙手手腕將亮起**藍色換彈光環**）。

## 🔧 人體骨架偵測修復與技術優化紀錄

針對先前版本中「人體偵測無法偵測骨架標記點」之問題，進行了深度排查與全面優化：

### 1. 原功能失效核心原因分析 (Root Causes)
1. **偵測循環競態提前終止（致命 Bug）**：
   - 原代碼在主選單點擊開始時呼叫 `await poseController.init()`，其內部立刻執行 `this.detectPoseLoop()`。
   - 但此時遊戲狀態 `AppState.isPlaying` 尚未被設為 `true`，導致 `detectPoseLoop` 第一行的 `if (!AppState.isPlaying) return;` 立即命中並退出，且沒有安排 `requestAnimationFrame`，導致**整個姿態偵測循環在第一幀就永久中斷**。
2. **依賴套件過舊與 TFHub CORS 問題**：
   - 原程式引用了 `@tensorflow-models/pose-detection@2.0.0` 與分散的 `tfjs-core@3.20.0`。
   - 舊版 MoveNet 預設透過已棄用的 `tfhub.dev` 網址取得模型權重，現代瀏覽器會因跨域重新導向（CORS）阻擋而載入失敗。
3. **骨架標記與骨骼連線未完整實作**：
   - 原 `drawSkeleton` 僅單純繪製置信度大於 `0.4` 的圓點，未繪製人體骨架骨骼連接線，且門檻過高容易在一般室內光線下完全看不見任何標記點。
4. **畫布 (Canvas) 與鏡頭 (Video) 比例錯位**：
   - 原先 `<video>` 設定了 `object-cover`，但疊加的 `<canvas>` 未設定相同的適配樣式，導致標記點即使畫出也會與影像位置脫節。

---

### 2. 本次修復與升級重點 (Key Improvements)

1. **升級 TensorFlow.js 核心與 MoveNet 模型**：
   - 升級至官方穩定版 `@tensorflow/tfjs@4.17.0` 與 `@tensorflow-models/pose-detection@2.1.3`。
   - 初始化前執行 `await tf.ready()` 確保 WebGL 硬體加速後端正常就緒，解決模型載入與算子缺失問題。
2. **重構生命週期與非同步偵測循環**：
   - 引入獨立的 `this.isRunning` 旗標與完整 `try...catch` 錯誤容錯保護，防止單幀運算波動中斷循環。
   - 支援遊戲結束 (`endGameMission`) 時主動呼叫 `poseController.stop()` 釋放網路攝影機資源。
3. **完整 17 處人體關節點與 16 條發光骨骼連線視覺化**：
   - **16 條人體骨骼連接線**：頭部五官、雙臂（肩-肘-腕）、軀幹（雙肩-雙髖）、雙腿（髖-膝-踝），以高對比青色霓虹光暈繪製。
   - **關節標記點分色與高亮輪廓**：五官天藍、肩肘翠綠、手腕琥珀、下肢紫色，均自帶抗背景雜色的純白邊框。
   - **動作即時視覺反饋**：右手舉起開火時手腕呈現紅色光環；雙手舉起換彈時雙手呈現藍色光環。
   - **即時追蹤點數 HUD**：右上角畫中畫視窗即時顯示如 `17 PTS DETECTED`，方便使用者調整距離與站位。
4. **體感操控手感全面調校**：
   - **修正轉向方向**：身體向右傾斜轉向右方、向左傾斜轉向左方，符合直覺操作。
   - **自適應肩膀距離 (Adaptive Calibration)**：動態計算基準肩寬，適應不同使用者身高、坐姿與攝影機距離。
   - **優先判定換彈手勢**：雙手舉起換彈判定優先於單手開火，徹底杜絕換彈時的誤射現象。

## 🛠️ 如何自訂遊戲數值與參數

若您想微調遊戲參數或靈敏度，可直接編輯 `3d_cs_pose_controlled_fps.html`：

1. **調整玩家移動速度與血量**：
   在 `FPSGameEngine` 類別中搜尋 `velocity` 運算區域微調移動係數。
2. **調整開火頻率與判定閾值**：
   搜尋 `PoseControllerManager` 的 `interpretGestures` 方法：
   ```javascript
   // 調整右手舉起觸發射擊的靈敏度 (數值愈大需舉愈高)
   const isRightUp = rightWrist && rightShoulder && rightWrist.y < rightShoulder.y - 12;

   // 調整射速限制 (毫秒，數值愈小射速愈快)
   if (now - this.lastShotTime > 180) { ... }
   ```
3. **調整人體關節點置信度閾值**：
   搜尋 `drawSkeleton` 與 `interpretGestures` 中的 `minScore`（預設為 `0.25`）。

## 📌 注意事項
- **硬體效能**：TensorFlow.js 即時姿態預測（MoveNet Lightning）結合 Three.js 3D 場景需使用 GPU WebGL 加速，建議在配備獨立顯卡或較新 CPU 的電腦上執行。
- **光線與站位**：使用 AI 體感模式時，請確保室內光線充足，並與攝影機保持 1.2 ~ 2 公尺距離，讓上半身完整出現在畫中畫視窗內。
